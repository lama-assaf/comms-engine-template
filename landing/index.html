the learning loop

Six rules it keeps.

The loop is only worth running if it can be trusted with your name. These hold in every session, scheduled or not.

  1. 01

    Drafts only.

    Nothing goes out on its own unless your stream's row says so under autopilot. The default is nothing.

  2. 02

    One variable per hypothesis.

    Named on every draft, with the planning query it answers.

  3. 03

    A predicted band on every draft.

    Below, baseline or above, recorded before it leaves the queue so it can be scored against what happened.

  4. 04

    Numbers and names wait.

    Statistics and named counterparties hold for human review.

  5. 05

    Claims come from the register.

    Or from a primary source cited in the piece. Nowhere else.

  6. 06

    Patterns, never people.

    Replies and comments are summarised as counts and shapes, never stored per person.

and what it never does

  • neversends past the gate
  • neverloads a schedule on its own
  • neverreads a token from a file
  • neverstores a person's name or handle in a record

get started

The first hour.

Clone it, name your business once, and read every dry run before anything is switched on.

  • macOS, for the launchd schedules and the keychain
  • python3, and Node 20 or later for the desk
  • Claude Code, plain claude, logged in
  • the atelier, salon and motion plugins
  • a twitterapi.io key, kept in the keychain
from the root of your clone

  1. 1name the business once

    engine init --slug yours --name "Yours"

  2. 2check the clone, one line per check

    engine doctor

  3. 3point it at your strategy documents

    engine setup corpus --root <dir>

  4. 4switch on the first schedule, after its dry run

    engine enable cycle

  5. 5open Claude Code in the folder and run a cycle

    /social-cycle
